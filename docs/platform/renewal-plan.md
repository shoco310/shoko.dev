## 0. V2MOM の原稿（受領済み）

原稿: 「さとうしょうこ V2MOM 2027｜理念・重点政策・成果指標（草案）」（Notion の PDF 書き出し、2026-11-20 受領。ステータス: 政策・V2MOM草案 v1.0、2026年11月4日）。**サイトに載せる文章は、この原稿から抜き出すだけにし、書き足さない。**

### サイトに使う原稿（そのまま転記する部分）
| 要素 | 原稿の内容 |
|---|---|
| Vision | 「誰もが挑戦できる宇部へ。『やってみたい』を、諦めなくていい街。」＋説明文（「人は、環境と選択肢によって変わる。…そんな宇部を目指す。」）。中心思想「人は、環境と選択肢によって変わる。」 |
| Values | 1. 選択肢を増やす（知る）／2. 自分で選べる（選ぶ）／3. 実現できる環境をつくる（実現する）。それぞれ説明1文＋「政策判断の問い」 |
| Methods | 4分野の表（分野／目指す状態／施策の候補／最初の調査）。横断する行動原則3つ（現場から始める／オープンである／行動し、改善し続ける）。実行プロセス「知る → つなぐ → 試す → 測る → 改善する」 |
| Obstacles | 5つの障壁と「確認・対応すること」の表（情報格差／出会いの不足／時間・経済・移動の制約／既存制度の使いにくさ／財源・制度・権限の制約） |
| Measures | 3層（Output／Outcome／Impact）、初年度の暫定活動目標4つ（2027年4月以降の12か月を想定・未確定）、注記、「声の収集」の定義、分野別の成果指標候補 |
| 公開しない | 実行ロードマップ（案）、政策調査・確認事項（未完了）、参照資料（Notion 内部リンク） |

### 原稿の「Web掲載の方向性」から設計に取り込むこと
- **V2MOM は独立したページ**（原稿は `/vision` を想定）。政策の詳しい施策・根拠は政策ページ、寄せられた声と対応は市民の声ページ、実績は活動ページ。**同じ長文を重複掲載しない。**
- V2MOM ページの表示順: ① Vision と短い説明（「挑戦を強いるのではなく、やりたいときに選べる環境を増やす」を明記）② Values を3枚のカード ③ Methods は4政策の概要のみ＋詳細へのリンク ④ Obstacles は簡潔に、調査で更新する前提を明示 ⑤ Measures は暫定目標・実績・最終更新日。**実績が未取得なら数値を作らず「集計準備中」** ⑥「市民の声を届ける」「活動の進捗を見る」へのリンク。
- 暫定数値は「目標案／未確定」と明示し、達成済みのように見せない。更新履歴を残し、変更理由がわかるようにする。

### Measures の実績の出し方（数値を作らない）
| 指標 | 仮目標 | 実績の出し方 |
|---|---|---|
| 市民・関係者の声の収集 | 100件 | 原稿の定義では Web投稿・対面ヒアリング・意見交換会・メール等の**合計**。Web の件数だけでは実績にならないため、自動集計はしない。運営者が集計した数値と集計日を手入力する（手入力の仕組みは §9 の任意項目）。それまでは「集計準備中」 |
| 政策・活動の月次報告 | 12回 | 公開済みの活動報告から数えられる（DB変更不要）。ただし対象期間（2027年4月〜）が始まるまでは「対象期間前」 |
| 重点政策の調査・提案 | 4本 | 数え方が原稿で未確定 →「集計準備中」 |
| 受け付けた政策提案の対応状況の記録 | 100% | 同上 |

原稿の注記「上記は本人活動の暫定目標案であり、市の事業成果を保証するものではない。2027年4月を目安に…目標値を確定する。」は表の下にそのまま載せる。

### 決定事項（2026-11-20 確定）
1. **ページの分け方**: メインメニューは「V2MOM・政策」1項目。中身は独立した2ページ＋既存の詳細。
   - `#/vision` … V2MOM（理念・価値観・行動原則・成果指標）。Methods では4政策を**簡潔に**紹介
   - `#/policies` … 4つの重点政策の一覧。各政策の目的・具体策を**比較できる**程度に詳しく
   - `#/policy/<slug>` … 既存の政策詳細4ページ
   - 長文は重複させない。ナビは両ページを選べる**ドロップダウン**（スマートフォンでは開閉できる小見出し）。
2. **政策の名前・キャッチ**: 正式名称とキャッチは**現サイトのまま**。V2MOM ページ内では原稿の表現（「知らない未来を選べる未来へ」など）を使ってよい。政策詳細の名称・キャッチは変えない。
3. **障壁の名前**: 原稿どおり「既存制度の使いにくさ」「財源・制度・権限の制約」。
4. **公開範囲**: 公開するのは Vision・Values・Methods・Obstacles・Measures。**実行ロードマップ（案）・政策調査・確認事項（未完了）・Notion 内部ページへのリンクは公開しない。** 暫定目標は未確定と明示し、実績がなければ「集計準備中」。
5. **市民の声と投稿フォーム**: 分離。`#/issues` = 市民の声の一覧・対応状況、`#/voice` = 投稿フォーム。既存 URL と投稿・承認機能は維持。

```
│ 目的：summary（現サイトの要約文）                              │
│ 主な取り組み：取り組みの見出しを最大5つ（箇条書き・本文なし）  │
│ [詳しく見る →]                                                │
└────────────────────────────────────────────────┘
… 02〜04 も同じ形（PC は2列×2段、スマートフォンは1列）
関連：数字で見る宇部／政策の変更履歴
```
- 文章はすべて既存の `src/data/policy.ts` から読む（名称・キャッチ・要約・取り組みの見出し）。新しく書かない。
- 長文（背景・取り組みの本文）は詳細ページだけに置く。

### 政策詳細（`#/policy/<slug>`）— 6ブロックに統一（**原稿は変えず、並べ替えと見出しの変更のみ**）

## 6. 活動ページ・市民の声ページの構成

### `#/activity` 活動（作り直し）
```
[見出し] 活動
[すべて] [活動報告] [イベント] [政策調査]   ← 絞り込み（ボタン、URLに反映）
これからの予定（イベント・あれば）
カード一覧（新しい順）：種類バッジ・日付・タイトル・要約 → 詳細／外部投稿
政策調査：4政策ごとの「確認済み／次に確認／今後の課題」（今の調査状況をそのまま）
```
- データは既存の **events**（予定）と **activity_reports**（報告）をそのまま使う。新しいデータの仕組みは作らない。
- 「政策調査」は、今は静的データ（`src/data/research.ts`）のみ。調査を報告として記事にしたい場合は、活動報告の種類に「政策調査」を加える小さな DB 変更が必要（任意・要承認）。

### `#/issues` 市民の声（作り直し）
```
[見出し] 市民の声
説明：送られた声は公開されず、佐藤祥子が読みます。承認したものだけを、個人が特定できない形で公開します。
[困りごとやご意見を送る]（→ #/voice）
対応状況のまとめ：受け止め N件／調査中 N件／提案・質問中 N件／政策に反映 N件（公開済みの課題から集計）
公開された声（課題）一覧：テーマ・状況・政策で絞り込み（今の機能）
声が政策になるまで：①声を集める → ②政策を改善 → ③活動を公開（今トップにある循環の説明をここへ）
```
- 投稿・承認・管理の仕組みは変更しない。公開には必ず承認が必要なまま。
- 投稿（市民の声）とボランティア登録（後援会）は、今どおり別の表・別のページで分ける。

## 9. 実装の優先順位と作業ステップ

各ステップごとに「プレビュー → 確認・承認 → 本番」。**DB 変更・削除・本番反映は承認後のみ。**

| # | 作業 | DB | 承認が必要なもの |
|---|---|---|---|
| 0 | V2MOM 原稿の受け取り・確認事項への回答（済） | なし | — |
| 1 | デザイントークンと共通コンポーネント（見た目の土台だけ。内容は変えない） | なし | プレビュー |
| 2 | ヘッダー（5項目＋参加する）・フッター（お問い合わせ・後援会・LINE の移動） | なし | プレビュー |
| 3 | 「私について」新設（ごあいさつ・プロフィールの全文を移動） | なし | プレビュー |
| 4 | `#/vision`・`#/policies` 新設、政策詳細を6ブロックに並べ替え | なし | プレビュー |
| 5 | 「活動」作り直し（予定・報告・政策調査の統合、絞り込み） | なし（「政策調査」の種類を足す場合のみ小さな変更） | プレビュー |
| 6 | 「市民の声」作り直し（対応状況のまとめ、循環の説明を移動） | なし | プレビュー |
| 7 | トップページを6セクションに再構成（2〜6 の完成後に行う） | なし | プレビュー |
| 8 | 仕上げ（画像の最適化、計測、アクセシビリティの再計測） | なし | — |
| 9 | （任意）Measures の実績と集計日をダッシュボードから手入力できるようにする。V2MOM の変更を「政策の変更履歴」に記録できるようにする | **小さな表の追加・種類の追加** | DB 変更 |

トップページを最後にするのは、移動先（私について、V2MOM・政策、活動、市民の声）が先にできていないと、内容が一時的に消えてしまうため。

## 10. 既存機能・データ・URL への影響とリスク

| 項目 | 影響 | 対策 |
|---|---|---|
| **トップのページ内リンク**（`#message` `#profile` `#support` `#contact` `#participate` `#take-part` `#events` `#activity`） | セクションを移すと、SNS などに共有されたリンクが行き先を失う | ルーターで新しい場所へ自動で案内する（例：`#message`・`#profile` → 私について、`#support` → 参加、`#contact` → フッター、`#activity` → 活動）。`#policy` はトップの政策セクションとして残す |
| `#/vision`・`#/policies`・`#/policy` の扱い | 2ページを新設。今は「見つかりません」になる `#/policy` は `#/policies` へ案内する | 既存の `#/policy/<slug>` には影響なし |
| `#/events` `#/issues` `#/activity` | 中身を作り直す | URL は維持。将来のパス形式でも同じ場所に案内する |
| 原稿の消失 | 長文・プロフィールの移動で消えるおそれ | 移動先を先に作り、トップの整理は最後に行う。移動前後の文章を照合する |
| 政策詳細の見出し | 見出しの名前が変わる | 本文は変更しない（並べ替えと見出しのみ）。更新履歴に「表示の整理」として記録するか、要相談 |
| 政策の名前 | 原稿と現サイトで名称・キャッチが違う | 決定どおり現サイトの名称・キャッチを維持。原稿の表現は V2MOM ページ内だけで使う |
| LINE の目立ち方 | ヘッダーの LINE ボタンがなくなる | 「参加する」とフッターに残す。登録数の変化を見る |
| 実績の表示 | 「声の収集」は Web 以外の声も含むため、Web の件数を自動で出すと実績を誤って見せる | 手入力の仕組みができるまで「集計準備中」。架空の数値は出さない |
| Google アナリティクス | ページの切り替え方は変わらないので、計測は続く。フォームのページで止める設定も維持 | — |
| Supabase・Turnstile・CSP・ダッシュボード | 変更しない | 各ステップで全ページの確認（今の自動確認）と、投稿・登録の動作確認を行う |
| 11/27 の URL 移行 | 別タスク | 新しいページはすべて `routeHref()` 経由でリンクし、移行時にまとめて切り替えられるようにする |
| 有料プラン | 変更しない | — |
